Photo Station Capture¶

Photo Station Capture drives a tethered Canon camera to photograph slabs, fills in the job details, and saves a JPG plus a metadata file that Mapper can read back later. It replaces walking a memory card back and forth between the photo station and the mapping PC.

Not the same as Photo Station calibration

This page covers the camera capture window. If you're looking for the pixels-to-inches calibration used by Auto-Crop, see Photo Station Setup instead — that's a separate, older feature with the same name for the same physical setup (a fixed camera position), but it doesn't involve a tethered camera.

Camera Setup¶

Photo Station Capture is built for Canon cameras (tested with the EOS R100; other EDSDK-compatible Canon bodies should also work).

  1. Connect the camera to the PC with a USB cable
  2. Turn the camera on
  3. Open Photo Station (see below) — it detects the camera automatically

You don't need to insert or format an SD card for this workflow: photos download directly to the PC and are never written to the card.

If the camera is turned on after the window is already open, it's detected automatically — there's no reconnect button to press. If the camera goes to sleep or is unplugged mid-session, Photo Station shows Waiting for camera… and reconnects on its own once it's available again; nothing you've already shot is lost.

Integrated vs Standalone¶

Photo Station runs in two forms:

  • Integrated — a window inside Mapper, for shops that photograph and map on the same PC. Open it from View > Photo Station.... Saved photos can be imported straight into the open project as a new slab.
  • Standalone — a separate, lightweight installer for a dedicated photo-station PC (e.g., in the fabrication shop, away from the mapping computer). It only does capture, form entry, save, and label printing — no DXF, no layout.

Standalone Licensing¶

The standalone app requires a license key on first launch, but it's not a second license — enter the same key you already use for Mapper. Activating Photo Station Capture does not consume one of your Mapper seats; it's tracked separately on the license server specifically so a shop can run a dedicated photo station without buying an extra seat.

Opening Photo Station¶

  • Integrated: the Photo Station button on the main toolbar, or View > Photo Station... in the main menu
  • Standalone: launch the Mapper Photo Station app directly

The window (or app) stays open across sessions the same way the Render Window does — closing it with the X hides it; it reopens instantly next time rather than restarting the camera connection from scratch.

Standalone window opens maximized

The standalone app opens maximized on launch (minimum size 900x600), so it fills a shop-PC monitor without you needing to resize it. Un-maximize any time if you'd rather run it in a smaller window.

Live view looks too dark?

The first time you open Photo Station, a one-time tip reminds you to open your camera's menu and set Exposure Simulation to Disable if the live preview looks unusually dark. This only affects what you see on screen — your saved photos keep their normal exposure either way. Check "Don't show this again" to dismiss it for good.

Form Fields¶

Field Required Notes
Job Name Yes Upper-cased automatically in the saved filename
Stone Color Yes Title-cased automatically in the saved filename
Thickness Yes Dropdown — options editable in Settings
Length No In inches; appears in the filename only when Height is also filled in
Height No In inches; appears in the filename only when Length is also filled in
Material No Dropdown — options editable in Settings
Slab # No Omitted from the filename if blank

Job Name, Stone Color, and Thickness are required to save a photo or print a label — you can print a label from the form alone, without taking a photo first.

Live View, Take, and Retake¶

While the camera is connected and you haven't just taken a shot, the preview panel shows a live feed from the camera, marked with a LIVE VIEW badge in the top-left corner so you always know you're looking at the live stream rather than a captured photo. Press TAKE PHOTO (or Enter) to capture — the shot appears in the preview and is added to the session's history strip (the vertical filmstrip to the right of the preview).

  • Click any thumbnail in the filmstrip to review that shot (this is what Save will use)
  • Double-click a thumbnail to open it full-size in a popup — scroll the mouse wheel to zoom in/out (centered on the cursor), drag to pan, double-click the popup or click Fit to reset, Escape or Close to dismiss. Handy for checking focus or pattern detail before you move on
  • Click Back to live to return to the live feed and take another shot
  • Reset clears the whole session's shots and form fields

If a capture doesn't come back within about 10 seconds, Photo Station shows a timeout error and returns to live view — check the cable and try again.

Save Behavior¶

There are two save buttons, both acting on the currently-selected shot:

Button Clears Use when
Save & Next Slab Only Length, Height, and Slab # Shooting a batch of slabs for the same job and stone — Job Name, Stone Color, Material, and Thickness stay filled in
Save & Clear Every field Moving on to a different job or stone

Slab # is always left blank after saving rather than auto-incremented — slabs are often shot out of numeric order, so Mapper doesn't guess at the next number.

Either button writes the currently-selected shot as a JPG using your filename template (see below). If a file with that name already exists, Mapper adds (2), (3), etc. — it never overwrites an existing photo.

Clear filmstrip on save (checkbox above the save buttons, on by default): after a successful save, the entire filmstrip is cleared — not just the saved shot — so an old photo can't be saved for the next slab by mistake. Untick it if you deliberately shoot several slabs before saving any of them; saving then removes only the selected shot and keeps the rest.

Filename Templates¶

The saved filename is built from a template of {Token} placeholders, editable in Settings (see below). The default template is:

{JobName} - {Thickness} {StoneColor}[ #{SlabNumber}][ - {Length}x{Height}]

which produces names like SMITH KITCHEN - 3cm Calacatta Gold #2 - 130x78.jpg.

Square brackets [ ... ] mark an optional group: everything inside — including spaces, #, or - — is dropped together whenever any token inside it is empty. That's why the slab-number and dimensions portions disappear cleanly from the name instead of leaving a stray # or -.

Token Value
{JobName} Upper-cased
{StoneColor} Title-cased
{Material} As selected in the dropdown
{Thickness} As selected in the dropdown
{SlabNumber} Blank if not entered
{Length} / {Height} In inches; blank if not entered
{Date} yyyy-MM-dd, at save time
{Time} HHmmss, at save time

Dimensions are all-or-nothing

The [ - {Length}x{Height}] group only appears when both Length and Height are filled in — entering just one drops the whole segment from the filename (the value you did enter is still saved if you're writing a sidecar, just not reflected in the name).

JSON Sidecar (off by default)¶

Mapper can optionally write a matching .json "sidecar" file alongside the JPG (metadata: job, color, material, thickness, slab #, dimensions, capture time, camera model). As of this version, the sidecar is off by default — turn it on in Settings if you want it.

Why you'd want it on: it's what lets Add Slab on the mapping PC prefill the name, material, thickness, and dimensions automatically when you load a saved photo. Without it, Add Slab falls back to parsing the filename instead — which recovers job name, stone color, and dimensions (if your template includes them), but not Material, since there's no filename-parse equivalent for it. If you want Material to prefill without the sidecar, add {Material} to your filename template so it's at least visible in the name for reference.

Where photos are saved:

  • Integrated: a Photos subfolder next to your .map project file. If the project hasn't been saved yet, photos go to the default folder configured in settings instead.
  • Standalone: the folder configured in the app's Settings dialog — typically a synced folder (OneDrive or similar) that's also reachable from the mapping PC.

Cross-PC workflow: if you shoot on a standalone photo-station PC and map on a different PC, point the standalone save folder at a folder that syncs to (or is shared with) the mapping PC. If the sidecar is turned on, once the JPG and its .json file arrive there, opening that photo in Add Slab on the mapping PC prefills the fields automatically — this is the entire integration between the two machines. With the sidecar off, filename parsing does the same job for whichever fields your template includes.

Tip

Add Slab reads a sidecar for any image you load, not just ones saved from Photo Station — as long as a .json file with the same name sits next to the .jpg.

Save on the Integrated Window¶

When Photo Station is running inside Mapper, either save button does both of the following:

  1. Writes the JPG (and sidecar, if enabled) to the Photos folder, exactly as standalone does — this is your permanent record
  2. Opens the normal Add Slab dialog for that photo, pre-filled from the form, so you can crop and add it to the open project right away

Label Printing¶

Click Print Label to print a 4"x3" label (at 300 DPI) with the job name, stone color, material, thickness, dimensions, slab number, date, and a QR code encoding the same metadata as the sidecar. It works with just the form filled in — a photo isn't required.

Set the printer used in Settings (standalone) or your usual print settings (integrated).

Settings¶

  • Thickness / Material options — comma-separated lists, editable in the Settings dialog (standalone) or the app's settings (integrated)
  • Save Path — the default photo/sidecar folder
  • Printer — which printer label prints go to
  • Filename Template — the token template used to name saved photos (see Filename Templates above), with a live example preview underneath the field so you can check your changes before saving. Leaving it blank restores the default template
  • Also write a .json sidecar next to each photo — checkbox, off by default (see JSON Sidecar above)

Where to find Settings: in the standalone app, File > Settings; in the integrated window, the Settings button in the top-right corner. Both open the same dialog. On the integrated window, the Save Folder is only a fallback used while the project hasn't been saved yet — once it has, photos always go to the Photos folder next to the project file.

Troubleshooting¶

Camera not detected

  • Confirm the USB cable is connected and the camera is powered on
  • Try a different USB port or cable
  • Make sure no other application (including Canon's own EOS software) is already connected to the camera — EDSDK cameras can only be controlled by one application at a time
  • Restart Photo Station if the camera was plugged in before the app started and still isn't showing as connected

Photos aren't prefilling in Add Slab

  • Check whether the sidecar checkbox is turned on in Settings — it's off by default, so if you haven't enabled it, prefill is coming entirely from filename parsing, and Material won't prefill (add {Material} to your template if you need it visible)
  • If the sidecar is on, check that both the .jpg and its matching .json file made it to the folder you're loading from — if only the photo synced (some sync tools can lag on small files, or a firewall/AV tool may have blocked one), the prefill data won't be there
  • The sidecar must have the same filename as the photo (just a different extension) and must not have been renamed independently of it

Save fails with a folder error

  • For the integrated window: save the project first, or set a default photo folder in settings
  • For standalone: set a save folder in the Settings dialog before saving
